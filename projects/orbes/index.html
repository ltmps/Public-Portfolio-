Detail B · Architecture

From sensor readings to motor commands.

Every request passes two checks: do the sensor frames agree, and can fourteen thrusters produce the force and torque?

  1. 01 · EstimateFuse inertial, magnetic and camera data into state estimates.
  2. 02 · DecideAttitude and translation control picks the response.
  3. 03 · AllocateSplit force and torque across the fourteen thrusters.
  4. 04 · ActMotors respond and sensing closes the loop.

Test stories

Detail C · Follow the mismatch to a smaller test

Story 1 · State estimation

Yaw aligned. Roll still disagreed.

Hanging tests exposed a camera/IMU frame mismatch. A two-state Kalman test for yaw and body-rate bias isolated the transient before testing returned to all three axes.

Story 2 · Actuation

A command can ask for too much.

Some requests fell outside the thrusters' feasible wrench envelope. Flooring negative fallback commands could leave zero output, so requests were scaled toward feasible commands.

Lessons

Check the estimate, then the command

General notes

  1. Check every axis after a frame correction.
  2. Check what the motors can produce.
